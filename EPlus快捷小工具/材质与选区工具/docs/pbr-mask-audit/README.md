# 五选区材质升级记录

当前已正式推广离线细节材质，详见[推广记录与异常项](rollout.md)及[批处理工具说明](../../tools/mask-batch/README.md)。下文保留初次改造时的数据协议记录；旧的实时提亮曲线已由 `目标颜色 × 选区图细节强度` 替代。

## 当前规则

- 基础贴图 RGB 保留原图细节，基础贴图 alpha 保持原来的透明/发光用途。
- 选区图 RGB 标识红、绿、蓝、黄、品红五区；有效区域的 alpha 直接表示基础金属度。
- alpha 为零不再使选区失效。透明但仍有选区 RGB 的像素会成为可染色的非金属区域。
- 粗糙度仅从原始基础颜色推导，不受换色结果或选区 alpha 影响。
- 用户金属度、粗糙度为零时自动；非零时使用 78% 用户值与 22% 基础值。普通、流畅、移动和兼容材质共享此规则。
- 玻璃度、炫彩度仍按原协议保存和打包，shader 保留解包入口，尚无视觉效果。
- RGB 的最大通道值现在保存离线生成的细节系数，材质直接乘以目标颜色，不再加入原图色彩残差、强制冷色或实时提亮曲线。纯色选区源图先通过工具转换，再放入资源包。
- 已淘汰首版偏平的细节公式：它将原图亮度 0.2 到 0.8 压到约 0.81 到 1.02，目标纯白时，原图亮度 0.65 以上全部被截为白色。新曲线优先保留细节，因此深色底图选择亮色后会比首版更暗。

## 配色状态与数据兼容

`ep_skin.pbr` 及其五组四参数的结构不变。新增可选 `tint_mask`，使用低五位记录每一区是否真正启用了 RGB 染色：红 1、绿 2、蓝 4、黄 8、品红 16。

该整数通过 `EXTRA_ACTOR_UNIFORM2.z` 传入，不增加 uniform 槽位，也不影响枪火使用的槽位 3。这里将原计划的整体开关细化为选区开关，是为了允许只修改 PBR 时保留原图，并区分明确选择纯黑与未修改颜色。

旧皮肤没有该字段时，按原有行为推导：开启 paint 且 RGB 非零的区域启用染色；旧零 RGB 区域保持原图。旧皮肤同样使用新材质与换色算法。新皮肤可以明确保存黑色。最小皮肤码在原有 PBR 数据后追加一个字节；JSON 皮肤码同步保存该字段。

## 资源与绑定

`summary.json` 记录审计范围及缺图引用；`textures.csv` 逐图记录有效选区像素、alpha 分布和透明 RGB；`bindings.json` 记录默认渲染的静态接入检查。

此次审计共 15 个项目、374 张选区图、743 处配置引用：

- 1 张图含 alpha 为零的有效选区像素，未改写原图。
- 16 张图的有效选区全部不透明，升级后默认金属度为 1，用户滑条仍能调整。
- 2 处缺图：`emx_muzzle_am_color_mask`、`snowballgun_color_mask`，运行时回退普通材质。
- 122 处渲染定义在静态模拟中切换到已有的选区控制器，无新增控制器缺失；这不是独立枪械数量。

主包统一处理第一人称、装配预览、掉落/第三人称实体及配件，不批量重写附属包配置。已有显式选区配置优先；同名 `_color_mask` 资源可通过构建期资源索引自动接入。只有现有支持的枪械/配件控制器参与自动切换，镜片和瞄具画面不参与。切换到其他基础贴图时不会直接套用原枪的默认选区图。

`pbrMaskResources.py` 是构建期索引，游戏不会扫描磁盘或逐帧读取图片。新增、删除选区图后，需要在包含全部附属包的工作站重新运行审计工具，再运行绑定检查。显式配置的新路径不受已有可用资源索引限制；修复已有缺图后也应重建索引以移除缺图记录。

## 已完成验证

- `python tests/test_pbr_mask_material.py`：9 项 Python 2.7 测试，包括预留参数和新旧皮肤码往返、纯黑状态、缺图回退、五选区打包、滑条切换、枪火槽位隔离及基础贴图切换。
- `tools/audit_pbr_masks.py`：使用 Python 3 + Pillow，解析审计范围内配置并生成报告、资源索引。
- `tools/verify_pbr_bindings.py`：使用 Python 3，检查跨包控制器引用。
- `tools/check_pbr_mask_gl.py`：使用 Windows Python 3，创建隐藏 OpenGL 上下文与离屏缓冲，编译共享 GLSL 并验证实际输出像素；不是游戏完整 shader 编译或移动 GLES 验证。
