# 军械库射击曲线与相机后坐力调校经验

记录日期：2026-09-22。适用场景：将枪械从旧的逐发增量后坐力迁移至平滑、可控的连续相机轨道；尤其需要兼顾触屏压枪、配件反馈和不同枪种性格。

> 首批 59 把有全自动模式的基础枪已由用户实机确认通过；随后新增 9 把机枪配置并通过静态测试。半自动/点射/半自动霰弹枪曾试调，但因后坐力过小已完整撤回，后续需要提高逐发冲击后重新设计。手动循环与特殊机制武器尚未迁移。下面的基准值属于按枪种设计的起点，不是全枪械最终标准。

## 先审计，再选择迁移对象

1. 枚举当前实际加载的枪械配置及其 `bind` 变体；核对 `selectData`、发射方式、开火间隔、`shootDown`、动画资源和配件绑定。不要仅凭 `gunType` 或根配置的 `fireType` 判断：有冲锋枪被标为手枪或狙击枪，也有单发、点射与全自动在模式切换后改变行为。
2. 拉栓、泵动、杠杆、转轮、充能、过热、双持、制导和发射实体等应先列例外，逐类评估。看似普通的左轮若遗漏在候选清单中，也应补进暂缓范围；不要把特殊武器直接套用连续自动曲线。
3. 装配潜力统计的是**确有至少一个选项能改变垂直或水平后坐力的槽位**，不是可见槽位总数。先解析绑定配件及继承覆盖，再比较枪种、射速和等级；枪种性格优先，等级与槽位仅作有限微调。
4. 审计时留存每枪旧值、建议裸枪值、装配界面的两项评分、开火 Camera 两通道、继承关系及例外原因；分枪种实施，上一批实机确认后再继续下一批。

## 弹道与镜头的职责边界

- 玩家镜头的连续连射后坐力交给 `CameraTrackMixer` 的 shootDown 二阶轨道；原有移动姿态、其他动作轨道和手动转向处理保持独立。只给显式启用 `shootDownMode: "curve"` 且配置 `shootDownProfile` 的枪生成新曲线；旧枪继续读取原 `shootDown` 数组及旧路径。
- `shootDownProfile` 生成一个中性点和一整周期的逐发点：低频正弦水平变化、轻微垂直波纹；周期边界连续，长期水平均值接近零。不要把相同的 24 点曲线复制给所有枪。快射枪应采用更长、更平滑的水平周期；重型枪可以提高抬升增益和上限，但保持有限幅度，避免帧间跳变。
- 可选 `variation` 是按射击轮次与发数生成的**有界、可复现、低频**水平微扰，而不是每帧抽随机数；固定曲线枪填 0。它不改变子弹弹道或散布。停火弹簧转向零目标；如果玩家主动移动镜头，应保留其转向，不强行拉回开火前的准星。
- 首发通常由开火 Camera 表现，后续自动射击由 Mixer 曲线接续。务必核对**实际首发选中的 Camera**：高速全自动枪可能优先使用 `fire2Camera`，而 `fireCamera` 的俯仰有时完全不同。仅当首发 Camera 缺少有效俯仰时才考虑 `shootDownFirstShot: true`；否则同时加首发曲线会双倍抬枪。
- 逐发 Z 轴翻转能提供力量感，但上下摇晃宜小，尤其低帧率移动端。模型视觉摆动可以继续存在，不要把它误当成第二套玩家相机后坐力。

## 配置接口及换算

下例只示意字段语义，不应直接复制到另一把枪；示例数字都必须按该枪的裸枪值与 Camera 轨道重新评估：

```json
{
  "recoil_vertical": 4.9,
  "recoil_level": 4.7,
  "shootDownMode": "curve",
  "shootDownProfile": {
    "period": 28,
    "pitch": 0.54,
    "pitchWave": 0.068,
    "yaw": 0.18,
    "phase": 0.34,
    "variation": 0.03,
    "cameraBase": [4.9, 4.7],
    "cameraWindow": 0.32,
    "cameraCaps": [2.4, 0.45, 1.3]
  },
  "shootDownFirstShot": false,
  "shootDownRecoilReference": 4.8,
  "shootDownRecoilSensitivity": 1.8,
  "shootDownSpeedSmoothing": true,
  "shootDownVerticalGain": 0.91,
  "shootDownVerticalCap": 25.0,
  "shootDownShakePitch": 0.12,
  "shootDownShakeYaw": 0.04,
  "shootDownShakeRoll": 0.95
}
```

- `pitch`、`yaw` 是归一化逐发曲线输入，不是相机角度，也不是装配 UI 的 0–100 分。界面分由运行时后坐力值经每枪自己的上限、下限换算并截断；改运行时值后，要重新核对 UI 分和实际手感。
- `shootDownRecoilReference` 是裸枪后坐力倍率基准；垂直与水平属性的配件变化分别影响抬升、横摆与相应的模型反馈。`shootDownVerticalGain` 决定逐发累计抬升，`shootDownVerticalCap` 限制持续连射的累计高度；二者不能互相替代。ADS 继续沿用原有后坐力缩放。
- `cameraBase` 分别记录首发 Camera 的裸枪垂直/水平数值，避免裸枪默认值被误缩放；`cameraCaps` 分别限制裸枪俯仰、偏航、翻转峰值。配件改变时，在基准限幅上再乘属性比例，所以不能用固定的总上限抹掉配件反馈。
- `cameraWindow` 是**真实秒数**。原 Camera 常按较低 `fireCameraSpeed` 播放，单看动画内部长度会低估实际持续时间。仅压缩 `camera` 骨骼的 `rotation` 关键帧，不改动画总时长、`ep_camera`、其他骨骼、位置、音效、粒子及 locator 的时间线；`pre/post` 与 Catmull-Rom 信息需要保留。末帧不归零时，预留平滑回零段。
- 瞄准 Camera 播放器本身已经执行瞄准缩放；自定义属性缩放时**不要再乘一次 ADS 比例**。停火时若系统会重播首发 Camera 作收尾，应将重播副本的 Camera 旋转清零，否则会在弹簧回正时额外踢一次镜头，其他事件与模型通道仍可保留。

## 继承、兼容与性能

- `bind` 会先取父配置，再按子配置字段覆盖；`data` 内同名字段并非无限深合并。若子枪裸枪值、首发 Camera 或曲线相位与父枪不同，要显式覆盖完整的 `shootDownProfile`、`cameraBase` 和必要的首发判定，不能只改一个后坐力数值。
- 旧增量后坐力、运行时独立相机冲量与新连续曲线属于不同机制；显式分流，未迁移武器保持原样。保留旧 `shootDown` 数据可作为回退依据。
- 生成的曲线与已缩放 Camera 动画应按枪械配置、有效属性与动画对象缓存；不要每发或每帧重复深拷贝整份动画，也不要让非迁移枪逐帧走额外分支。新代码须兼容 Python 2.7。
- 调整 Camera 前先看 `camera` 骨骼的实际旋转关键帧、层级和枢轴；引用动画名必须在该枪动画资源中存在，双射击通道两条都要验证。JSON 能解析不代表动画引用一定有效。

## 回归与实机验收

静态检查：全部入选配置可解析；`period` 和角度上限合法；水平曲线一周期均值接近零、首尾连续；范围扰动固定轮次可复现；首发、持续射击、停火与拖动视角分支分开；两条 Camera 引用都能解析；继承后的最终值正确；暂缓武器没有意外启用新字段。对修改的 Python 运行 Python 2.7 编译和后坐力定向测试，同时检查其他回归测试，不把既有未通过项误报为本轮已解决。

游戏中每批至少用裸枪、偏重垂直补偿、偏重水平补偿三种状态分别测试腰射和瞄准；在高、低帧率下分别看首发抬升、连续压枪、左右一周期净漂移、停止后的弹簧回正、主动拖动视角、换枪和两条开火通道。首批已完成该项实机验收并通过；机枪批次待验收。半自动/点射/霰弹方案若明显偏轻，应先撤回并提高逐发 Camera 峰值、垂直增益或独立回弹冲量，再重新请求实机验收。
