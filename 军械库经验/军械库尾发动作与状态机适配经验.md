# 军械库尾发动作与状态机适配经验

## 适用场景

用于“弹匣剩余最后一发时，播放与普通射击不同的第一人称动作和摄像机动作”的枪械。

典型需求包括：

- 最后一发使用独立的拉动、空仓、枪机后停或特殊退壳动作。
- 尾发动作必须完整播放后才能进入自动换弹。
- 尾发动作需要独立摄像机表现。
- 尾发动作不能与空仓静态姿态、普通后坐力或其它枪机动作发生冲突。

## 核心结论

### 1. 尾发动作适合使用状态机，不适合使用普通权重层

如果尾发动作会改变整把枪的基础姿态，或者必须完整播放到结束，应使用专用动画控制器状态：

```json
"last_shoot": {
    "animations": ["last_shoot", "static_idle"],
    "transitions": [
        {
            "static_idle": "query.mod.ep_last_shoot <= 0"
        }
    ],
    "blend_transition": 0.0
}
```

不要用普通 `blend_weight` 叠加尾发动作。权重层容易产生以下问题：

- 动画速度被动作层时间变量意外改变。
- 多次射击时旧 timer 覆盖新 timer。
- 尾发动作尚未完成就被换弹、空仓或静态动画覆盖。
- `static_idle`、`static_bolt_caught` 与尾发动作同时控制同一批骨骼，产生姿态叠加。

状态机中的普通动画字符串默认以完整权重播放。需要原速播放时，不要额外添加会改变动画时间的 `anim_time_update`。

### 2. 尾发状态必须保留基础 idle

`last_shoot` 不能只播放自身动作：

```json
"animations": ["last_shoot"]
```

这样可能导致尾发动画播放期间枪械失去基础持枪姿态，表现为枪械漂移、姿态断裂或局部骨骼异常。

应同时播放基础姿态：

```json
"animations": ["last_shoot", "static_idle"]
```

这里的 `static_idle` 是枪械的基础持枪动画。具体枪械如果使用其他基础姿态，应替换为该枪实际注册的 idle 短名。

### 3. `static_bolt_caught` 必须与 `last_shoot` 分离

空仓静态姿态不应直接加入 `last_shoot` 状态。尾发状态期间通过公共控制器条件屏蔽空仓姿态：

```molang
query.mod.ep_last_shoot <= 0 &&
(v.tac.bullet <= 0) &&
!(v.tac.state || v.tac.is_reload)
```

这样可以保证：

- 尾发过程中不会叠加 `static_bolt_caught`。
- 尾发结束后，如果已经进入空仓，空仓姿态可以正常恢复。
- 普通枪械的 `query.mod.ep_last_shoot` 为 0，因此不会改变原有行为。

## 最后一发判定

最后一发必须在扣除子弹前判断：

```text
is_last_shot = 当前不是无限弹药，并且开火前弹匣剩余数量 == 1
```

不要用扣除后的 `nowBullet == 0` 作为唯一判断依据，否则容易和空仓同步、弹药持久化或自动换弹时序混在一起。

推荐流程：

1. 播放普通开火音效。
2. 在消耗子弹前判断是否为最后一发。
3. 普通射击使用普通射击权重层。
4. 最后一发停止普通第一人称射击权重，设置 `query.mod.ep_last_shoot = 1`。
5. 执行原有弹道、伤害、粒子、第三人称表现和弹药扣除。
6. 尾发持续时间结束后，将 `query.mod.ep_last_shoot` 清零。

无限弹药、条件无限弹药或无法确认弹匣数量时，不应触发尾发动作。

## 运行时信号设计

建议只增加一个状态信号：

```text
query.mod.ep_last_shoot
```

推荐值：

- `0`：未处于尾发状态。
- `1`：尾发状态播放中。

脚本需要使用 token 或版本号管理结束 timer：

```text
触发时 token += 1
记录当前 token
设置 query.mod.ep_last_shoot = 1
启动 duration timer

timer 回调时：
如果 token 不是当前 token，直接返回
否则设置 query.mod.ep_last_shoot = 0
```

这样可以避免旧 timer 在切枪、死亡、重复触发后清掉新一次尾发状态。

## 摄像机处理

尾发摄像机应使用自己的配置和速度，不要复用普通射击摄像机的慢速参数：

```json
"last_shoot": {
    "mode": "state",
    "animation": "last_shoot",
    "camera": "animation.weapon.last_shoot",
    "duration": 1.0,
    "cameraSpeed": 1.0
}
```

关键规则：

- `cameraSpeed` 默认使用 `1.0`，避免沿用普通开火镜头常见的 `0.4`。
- 尾发摄像机存在时，优先播放尾发摄像机。
- 尾发摄像机缺失时回退普通开火摄像机，但仍不应让普通枪械报错。
- 尾发镜头播放期间应重置全自动射击镜头的抑制/释放状态，避免被全自动镜头逻辑覆盖。
- 摄像机动画长度应参与完整播放时长计算。

## 换弹同步

最后一发射击后，自动换弹不能立即开始。换弹入口需要检查尾发状态剩余时间：

```text
reload_delay = max(
    尾发动作剩余时间,
    尾发摄像机长度 / 尾发摄像机速度
)
```

如果仍在尾发窗口内：

1. 不立即执行换弹。
2. 设置 pending reload。
3. 启动一次带 token 的延迟 timer。
4. timer 到期后再次检查玩家死亡、切枪、检视、近战、换弹和开火状态。
5. 条件仍然有效时再进入原有 `StartReload()`。

取消等待时，不要随意清零尾发播放截止时间。只有以下情况应清理尾发状态：

- 切枪或收枪。
- 玩家死亡。
- 近战、检视或其它明确的硬中断。
- 枪械被禁用或资源被卸载。

普通的换弹重试、瞄准退出或 reload timer 取消，不应提前破坏仍在播放的尾发动作。

## 状态机结构建议

专用状态机应以该枪原本可用的状态为基础，只增加尾发状态，不要直接复制其它枪械的完整状态机。

至少确认以下动作短名存在：

- `draw`
- `static_idle`
- `reload_tactical`
- `reload_empty`
- `inspect`
- `inspect_empty`
- `put_away`
- `select_auto`
- `ep_melee`
- `last_shoot`

容易出错的做法是把左轮、栓动枪或逐发换弹枪的控制器直接复制给另一把枪。这样会引入该枪没有注册的：

- `bolt`
- `reload_loop`
- `reload_end`
- `shoot1`
- `static_idle_1`
- 特殊装填状态

正确方式是：

1. 以目标枪原有控制器为基础。
2. 保留目标枪已有的状态和动作短名。
3. 只新增 `last_shoot` 状态及相关转移。
4. 让普通 `shoot` 继续由现有射击权重层负责。
5. 让 `last_shoot` 状态只替换最后一发的第一人称普通射击动作。

## 普通射击与尾发射击的职责划分

普通射击：

- 使用现有 `shoot` / `shoot2` 权重层。
- 继续使用原有射击音效、弹道、伤害和第三人称表现。
- 继续使用原有射击计时和后坐力逻辑。

尾发射击：

- 跳过普通第一人称 `shoot` 权重，避免重复叠加。
- 通过 `query.mod.ep_last_shoot` 进入专用状态。
- 使用专用 `last_shoot` 动画和摄像机。
- 不改变弹道、伤害、弹药同步或第三人称开火逻辑。

## 配置隔离

建议尾发功能同时满足以下条件才启用：

```text
存在 actionOverlay.last_shoot
存在有效 stateController
存在有效 last_shoot 动画短名
存在有效摄像机时才启用摄像机替换
```

未配置尾发字段的枪械必须完全走旧逻辑。

推荐配置：

```json
"stateController": "controller.animation.ep_jxk.weapon_state",
"actionOverlay": {
    "last_shoot": {
        "mode": "state",
        "animation": "last_shoot",
        "camera": "animation.weapon.last_shoot",
        "duration": 1.0,
        "cameraSpeed": 1.0
    }
}
```

`stateController` 只覆盖枪械的 `ep_state`，其它瞄准、移动、跳跃和公共动作控制器继续沿用原配置。

## 常见问题与排查顺序

### 尾发动作速度很慢

检查：

- 是否仍存在 `blend_weight`。
- 是否仍存在 `anim_time_update`。
- 是否使用了旧的 `query.mod.ep_action_time_last_shoot`。
- 摄像机是否错误继承了普通 `fireCameraSpeed`。
- 是否把 `cameraSpeed` 配成了 `0.4` 或更低。

### 尾发动作只播放一次

检查：

- 是否使用了旧权重层的 runtime 缓存。
- 是否旧 timer 清掉了新动作的变量。
- 是否状态机没有从 `shoot1` / `shoot2` 返回或重新进入尾发状态。
- 是否每次触发前都递增 token。

### 尾发动作和空仓姿态重叠

检查：

- `static_bolt_caught` 是否仍在尾发期间生效。
- 公共控制器条件是否包含 `query.mod.ep_last_shoot <= 0`。
- 是否错误地把 `static_bolt_caught` 放进了 `last_shoot` 状态。

### 尾发时枪械姿态断裂

检查：

- `last_shoot` 状态是否同时播放 `static_idle`。
- `static_idle` 是否是该枪真实注册的基础持枪短名。
- 尾发动画是否错误地覆盖了整套基础姿态，而不是只控制需要变化的骨骼。

### 最后一发后立刻换弹

检查：

- 最后一发判定是否发生在扣弹前。
- `StartReload()` 是否经过尾发等待入口。
- 等待时长是否同时考虑动作长度和摄像机长度。
- reload timer 是否被其它取消逻辑提前清除。

## 静态验证清单

- Python 文件通过 `python -B -m py_compile`。
- 枪械配置、动画、状态机、摄像机 JSON 均可解析。
- `actionOverlay.last_shoot.animation` 存在于 `render.Animations`。
- `stateController` 名称与资源控制器名称一致。
- 状态机中的每个动画短名都存在于枪械注册表。
- `last_shoot` 状态包含尾发动作和基础 idle。
- `last_shoot` 状态不包含 `static_bolt_caught`。
- 尾发动画不使用旧权重变量或旧时间变量。
- 摄像机动画存在且速度为 1.0 或明确的枪械专用速度。
- 未配置尾发的枪械没有进入尾发分支。

## 游戏内验收清单

- 弹匣有多发子弹时，普通射击不受影响。
- 开火前剩余 1 发时，播放完整 `last_shoot`。
- 尾发期间基础 `static_idle` 姿态保持存在。
- 尾发期间不叠加 `static_bolt_caught`。
- 尾发摄像机按正常速度播放完整。
- 尾发完成前不会进入换弹。
- 快速切枪、死亡、检视、近战和收枪后不会残留尾发状态。
- 重新装填后普通射击动画可以正常恢复。
